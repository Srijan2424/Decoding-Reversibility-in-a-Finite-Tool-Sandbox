# Task 4 feasibility and transfer plan

As of 15 November 2026, the sandbox is usable for grouped evaluation. All three of its existing splits contain every class in each partition. The restricted ScienceWorld pilot supplies three distinct examples from one kitchen family. It contains two irreversible examples, one partial example and zero reversible examples. There are no local representation caches in the supplied workspace. The archived probe predictions can be used as reference evidence but are insufficient to fit a new probe or evaluate a new example.

## Data preparation

1. Retain the existing kitchen pilot as development evidence. Define at least three independent new scenario families for the minimum train/validation/test separation. Six families, with two in each partition, are a better initial pilot target if enough suitable cases exist. A family groups the starting layout and recovery mechanism together. Replays and variations of a shared mechanism/layout stay in the same partition.
2. Look for reversible cases first. Start with actions for which there is a plausible short undo sequence, such as opening and closing the same container, moving an item out and back, or connecting and disconnecting a circuit. Use conditions where the approved physical comparison can actually return to equality. These are candidate mechanisms, not assigned labels. Keep the field projection and legitimate recovery list fixed before collecting each evaluation family. Any revision to the state definition creates a new benchmark version.
3. Include exact and irreversible examples in each partition for a binary run. Include partial examples in each partition for a three-class run. For a pilot, target at least two distinct examples per included class per family. A complete bounded search or rigorous invariant supports a negative label. A replayable exact witness supports a positive label. Do not convert unresolved searches into labels or oversample duplicate projections. Verify class counts, distinct inputs, and group disjointness before feature extraction.
4. Use exact-recovery versus irreversible as the primary binary task to match the existing sandbox convention. Report partial-label transfer separately because the sandbox permits residual fees/older content while the restricted ScienceWorld rules permit temperature differences. Describe any three-class results as transfer between environment-specific operational labels. Preserve the difference in label semantics in the interpretation.

## Model work after the data check passes

1. Use the pinned Qwen and Llama revisions and the original inference configuration. Freeze the same task/state/action prompt structure and token pooling for both environments. Reuse saved sandbox features only if the prompt, tokenizer, revision, pooling, and activation settings match. Re-extract on GPU otherwise. Extract ScienceWorld features and retain a manifest linking tensors to dataset IDs and prompt hashes.
2. For each direction, fit a scaler and linear probe on source training groups. Choose layer and regularization on source validation groups. Freeze the probe before evaluating held-out target groups. Keep the original sandbox splits and use disjoint ScienceWorld partitions. Run within-environment and majority/action-label baselines on the same target examples. Check whether candidate verb alone predicts the class.
3. Report balanced accuracy and macro-F1, sample counts, confusion matrices and results by group. Use group-level intervals only when the number of groups supports meaningful estimates. With a tiny pilot, describe results as exploratory.
